# 543. Diameter of Binary Tree

https://leetcode.com/problems/diameter-of-binary-tree/

### Pattern
Recursive DFS with a side effect — one function answers two questions at once:
returns depth to its parent, and updates external state (global max) as it goes.
Post-order traversal (left, right, then node) is what makes this work in a single
pass: both children's depths are fully known before the parent checks its own
diameter, so every node gets evaluated exactly once.

### Brute-force idea
For each node in the tree, separately call maxDepth() on its left and right
subtrees and compare with global max — O(N) candidates × O(N) depth calculation
each = O(N²).

### Final approach
Single recursive function (depth) that, for each node, computes leftDepth and
rightDepth via recursive calls, compares (leftDepth + rightDepth) against a
global max field, and returns Math.max(leftDepth, rightDepth) + 1 to the parent.
The diameter check uses a pure sum (no +1); the returned depth uses max + 1.

### Time complexity
O(N) — each node visited exactly once.

### Space complexity
O(H) — recursion stack, H = tree height (worst case O(N) for skewed tree).

### Mistake / insight
Confused "depth" (what bubbles up, uses max) with "diameter at a node" (what
gets compared to global, uses sum, no +1). Also tried calling a separate pure
maxDepth() function instead of recursing into itself — this breaks the global
update at every node except the entry point.
